# Pitfall: Claude Code 2.1.290+ treats a gating hook (prompt.submit, tool.call, tool.check,

## Summary
Claude Code 2.1.290+ treats a gating hook (prompt.submit, tool.call, tool.check, classic.*, command.run, agent.spawn) that throws, times out or re-enters (HookFailure.kind 're-entry', cause 'lent') as skipped: the action goes on unless on(...).catch(($, e, next) => next.called ? next(e) : { deny }) answers in its place. claude plugin validate on 2.1.299 lists Navigator's 14 gating hooks as 'gating hook without .catch' (gatingHooks under --json). Navigator fails open by design, so this is a warning; adding a pass-through .catch keeps the policy and silences it.
Update from the GitHub changelog: since 2.1.301 the .catch runs only on throw or timeout; an event raised beneath the hook's own calls skips the hook without asking its .catch (the 2.1.299 re-entry handler lasted two releases).
