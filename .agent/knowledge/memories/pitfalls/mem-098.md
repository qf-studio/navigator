# Pitfall: Deploy QuantFlow AWS job cancelled mid-wait = infra "all" deploy replaced the runner

## Summary
Deploy QuantFlow AWS job cancelled mid CloudFormation wait = the infra "all" deploy replaced the quantflow runner machine (confirmed by Nelya 2026-10-08, not a job limit); wait for UPDATE_COMPLETE, then gh run rerun --failed so the CDN invalidation runs

## Context
Seen on tag prod-8.3.4-1791454963 (run 37763302446): the Deploy service job got
`##[error]The operation was canceled.` at 4m55s; the stack finished UPDATE_COMPLETE on its own.
Nelya traced it: the infra "all" deploy (machine patches) replaced the runner machine at 10:29:55
and both ECS machines at once, which also slowed the rollout. She pings before an "all" run;
the automated version will skip itself while an app deploy runs.
